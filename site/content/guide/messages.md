title: 知らせ方の選び方
order: 5.5
description: 結果・警告・エラー・空の状態を、どの部品で伝えるか
---

利用者に何かを伝えるとき、伝える内容と、伝える範囲（画面全体・画面の一部・項目 1 つ）で、使う部品が決まります。同じ種類の知らせを、いつも同じ部品で出すと、利用者は見た目から重さと次の行動を読み取れます。

## 早見表

| 伝えたいこと                                   | 部品                                                                                                                 | 消え方                               |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 操作の結果（保存した・送信した・削除した）     | 通知（`JimbleUI.toast()`）                                                                                           | 自動で消える（失敗は残る）           |
| 入力の誤り（項目ごと）                         | [Field](../../components/field/) の `error`                                                                          | 直すと消える                         |
| 入力の誤りの要約・画面の一部への注意           | [Alert](../../components/alert/)（その部分の上に置く）                                                               | 状況が変わるまで残る                 |
| 画面全体・アプリ全体に関わること（保守・期限） | [Banner](../../components/banner/)（画面のいちばん上）                                                               | 状況が変わるまで、または閉じるまで   |
| 先へ進む前に答えが要ること（削除の確認など）   | [Dialog](../../components/dialog/) の `alert`                                                                        | 答えると閉じる                       |
| 表示するデータがない（0 件・検索の結果なし）   | [Empty State](../../components/empty-state/)                                                                         | データが入ると消える                 |
| 読み込み中・処理中                             | [Skeleton](../../components/skeleton/)・[Spinner](../../components/spinner/)・[Progress](../../components/progress/) | 終わると消える                       |
| 状態の表示（公開中・下書き・期限切れ）         | [Badge](../../components/badge/)                                                                                     | 状態とともに変わる                   |
| 操作や項目の補足                               | [Tooltip](../../components/tooltip/)・Field の `hint`                                                                | 常に読める／ホバー・フォーカスで出る |

## 種類ごとの選び方

### 成功

操作の結果は、通知で短く知らせます（`JimbleUI.toast.success('保存しました')`）。画面がその結果を見せているとき（一覧に新しい行が出た）は、通知がなくても伝わります。何度も出す通知は、読まれなくなります。

### エラー

- **入力の誤り**は、項目の近くに出します（`jimble-field` の `error`）。項目が多いフォームでは、送信した直後に、誤りの要約を `jimble-alert variant="danger"` で上に出します。
- **操作の失敗**（通信の失敗・権限がない）は、通知の `variant: 'danger'` で知らせます。自動では消えません。やり直せるなら `action` に「再試行」を付けます。
- **画面を表示できない失敗**（データを読めない）は、その場所に `jimble-alert variant="danger"` を置き、何が起きたかと、次にすること（再読み込み・問い合わせ先）を書きます。

### 警告

まだ起きていないが、放っておくと困ること（期限が近い・保存していない変更がある・上限に近い）です。関わる部分の上に `jimble-alert variant="warning"` を置きます。契約の期限など、アプリ全体に関わる警告は、画面のいちばん上の `jimble-banner variant="warning"` にします。取り返しのつかない操作の直前に止めるときは、ダイアログの `alert` で確認します。

### 情報

知っておくとよいこと（仕様の変更・使い方のこつ）です。`jimble-alert variant="info"` を使い、読んだら不要になるものは `dismissible` にします。画面ごとに 1 つまでにします。

### データがない

一覧が空のときは、`jimble-empty-state` で、何がないかと、次にすること（最初の 1 件を作る・条件を外す）を書きます。読み込み中やエラーと区別します（読み込み中に「0 件」と出さない）。

## 文章の書き方

- **何が起きたか**と、**次に何をすればよいか**を書きます。「エラーが発生しました」だけで終えません。
  - 良い例: 「注文を保存できませんでした。通信を確認して、もう一度保存してください。」
  - 悪い例: 「エラーが発生しました（code: 500）」
- 色とアイコンだけで重さを伝えません。文字で読める必要があります（強制色モード・読み上げでは色が伝わりません）。
- 利用者を責める書き方をしません（「入力が間違っています」ではなく「メールアドレスの形で入力してください」）。
- ボタンの名前は、押すと何が起きるかを動詞で書きます（「OK」ではなく「削除する」）。

## 重ねない

- 1 回の操作で、通知とアラートとダイアログを同時に出しません。どれか 1 つにします。
- 画面に並ぶアラートは、多くても 2 つまでにします。増えるなら、1 つにまとめます。
- 読み終える前に消えては困る情報を、通知だけで伝えません（画面の中にも `jimble-alert` で出します）。

## 読み上げ

- 通知とアラートは、`danger` / `warning` ならすぐに読み上げられ（`role="alert"`）、`info` / `success` なら、読み上げ中の内容が終わってから読み上げられます（`role="status"`）。
- ページを開いた時点で置いてあるアラートは、読み上げの割り込みにならないよう、その画面に必要なものだけにします。
- 空の状態の見出しは、置いた場所の見出しの階層に合わせます（`level`）。
