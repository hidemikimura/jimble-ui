`<jimble-field>` は、中に置いたフォーム部品（`jimble-input`、`jimble-textarea`、`jimble-radio-group` など）にラベル・ヒント・エラーを付けます。仕組みは [フォームとの連携](../../guide/forms/) を参照してください。

## 独自の検証（`validate`）

`validate` プロパティに関数を渡すと、フィールド単位で独自の検証ができます。値を受け取り、**エラーメッセージ（空でない文字列）を返す**と、その文言がエラーとして表示されます。問題なければ `null` を返します。

::example field/custom-validation

```js
field.validate = (value, control) => (value ? null : '必須です。')
```

Lit のテンプレートでは、関数は**プロパティ**として渡します（`validate=` の属性では関数を渡せません）。

```ts
render() {
  return html`
    <jimble-field
      label="メールアドレス"
      hint="社用アドレスを入力してください"
      .validate=${(value: string) => (value ? null : '必須です。')}
    >
      <jimble-input type="email" name="email" @change=${(e) => (this.email = e.target.value)}></jimble-input>
    </jimble-field>
  `
}
```

- **いつ呼ばれるか**: 値が変わったとき（`input`・`change`）と、フォーカスが外れたときに呼ばれます。ほかに、**最初に 1 回**と、`validate` を差し替えたときにも呼ばれます。**空の値でも呼ばれる**ので、空を許すなら、空のときは `null` を返してください。値を自分で持たなくても、関数に値が渡されます（上の `@change` は、値をアプリの状態に保存したいときだけ書きます）。
- **いつ表示されるか**: エラーの表示は、これまでのエラーと同じく、**部品から一度フォーカスが外れたあと**（または送信を試みたあと）です。入力の途中では出ません。
- **送信は止まる**: エラーの間は、フォームの検証が通らず、送信されません（ネイティブの `required` などと同じです）。送信を試みると、エラーの出ている最初の部品にフォーカスが移ります。
- **渡される値**: テキスト・セレクト・日付などは文字列、チェックボックス・スイッチは真偽値、複数選択の Combobox・Dual Listbox は文字列の配列、File Input は `File` の配列です。2 つ目の引数は、その部品の要素です。
- **非同期**: `Promise` を返すと、サーバーへの問い合わせにも使えます（上の例のアカウント名）。結果が出るまでは「確認中です」となり、送信されません。`Promise` を返す検証は、入力のたびには呼ばず、値が確定したとき（`change`・フォーカスが外れたとき）に呼びます。古い結果は捨てられます。
- **1 つの `jimble-field` に部品が複数あるとき**（姓と名など）:
  - 検証は**部品ごと**に呼ばれ、エラーは、その部品に付きます。
  - 3 つ目の引数 `context` の `context.get('first_name')` で、同じ field の中のほかの部品の値を（`name` で）引けます。`context.controls` は、部品の一覧です。
  - どれかの部品の値が変わると、ほかの部品も（同期の検証なら）再検証されます（合計の文字数のように、ほかの値に依存する検証のため）。
  - `jimble-field` に出るエラーは、無効な部品のうち、**並びで最初のもの**です（片方を直しても、もう片方が無効なら、表示は消えません）。
  - 読み上げの部品の名前は、`jimble-field` の `label` に、部品の `aria-label` を足したもの（「氏名 姓」「氏名 名」）です。**部品には、`aria-label` で区別できる名前を付けてください。**

  ::example field/multiple-controls

- **外から実行する**（別の入力を受けて、この項目を検証したいとき。氏名から自動入力されるフリガナなど）:

  ::example field/kana

  - `await field.validateNow()`: 中の部品を**今すぐ検証**します（表示は変えません）。すべて問題なければ `true`。
  - `await field.showErrors()`: 検証して、**エラーを表示**します（送信を試みたときと同じ状態。触れていなくても出ます）。「フリガナをエラーにする」ときに使います。
  - `field.hideErrors()`: エラーの**表示だけを隠します**（値と検証の結果は変わらず、送信は止まったままです）。次にフォーカスが外れたり、送信を試みたりすると、また出ます。
  - **部品の値をプログラムから書き換えたとき**（`input.value = 'ヤマダ'`。イベントが出なくても）は、`validate` が**自動でやり直されます**。フリガナが自動入力されて有効になれば、エラーは自動で消えます。Autokana.js のように `value` を直接書き換えるライブラリと組み合わせられます。
  - 個々の部品の `setTouched(true / false)` でも、エラーの表示・非表示を切り替えられます。

- **例外**: 関数が例外を投げる・`Promise` が拒否されると、「検証できませんでした」というエラーになります。
- **ほかのエラーとの関係**: `setCustomValidity` で付けたエラーや、`error` 属性（サーバーからのエラー）とは別に扱われ、互いに上書きしません。ネイティブの制約（`required`・`type="email"` など）とは併用できます。
- **送信の直前に確定させたいとき**: `await field.validateNow()` は、中の部品をすべて今すぐ検証し、終わるまで待って、問題なければ `true` を返します。

## 注意

- 表示するエラーは、`error` 属性（明示）が優先され、なければ部品自身の検証メッセージ（触れた後）が出ます。
- 見えているラベル・ヒント・エラーは、中に `jimble-*` のフォーム部品があるときだけ支援技術から隠されます（部品側が同じ文言を持つため）。ネイティブの `<input>` を中に置く使い方には対応していません。
- ラベルをクリックすると、中の部品にフォーカスします。
